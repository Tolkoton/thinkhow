# Звіт задачі 106 — Голос і мова людини (F13)

## Що змінилось для власника
- **Мова людини.** При першому вході людина бачить сторінку «Мова» і обирає свою мову зі списку з 85 мов (назви — мовою
  самої мови: «Українська», «Polski», «English (United States)»…). Російської в списку немає, і сервер її не приймає.
  Змінити мову можна будь-коли за посиланням «Мова» вгорі кожної сторінки. Мова лежить у `users/<id>/profile.json`.
- **Голос.** У полі репліки є кнопка «🎤 Говорити». Натиснули — говорите — натиснули ще раз. Через секунду-дві (для
  кількох хвилин мови — кілька секунд) текст з'являється в полі, дописаний до того, що там уже було. Ви його правите
  і надсилаєте звичайною кнопкою. Якщо розпізнати не вдалося, запис лишається на сторінці, і кнопка «Розпізнати ще
  раз» надсилає його знову. Один запис — до 14.5 хв: рекордер зупиняється сам.
- **Модель розпізнавання — `gemini-3.5-transcribe`** на Vertex AI в регіоні `eu`, мова закріплена з профілю
  (ADR-0005). Звук ніде не зберігається — лише текст.
- **Фасилітатор відповідає мовою з профілю і ніколи — російською**, навіть коли людина пише російською.
- **Розгортання не змінюється**: ті самі API й права (`aiplatform.googleapis.com`, `roles/aiplatform.user`), нових
  змінних задавати не треба. Новий образ і розгортання — ті самі кроки 5 і 8 з `docs/deploy.md` (задача 105).

## Демонстрація на хвилину (локально)
- `uv run python scripts/smoke_test_voice_language.py` — перший вхід веде на «Мова», вибір `pl-PL`, «Мова: Polski»,
  відмова `ru-RU`.
- `uv run --with playwright==1.64.1 python scripts/smoke_test_voice_dictation.py` — справжній Chromium з фальшивим
  мікрофоном: мова → тема → «🎤 Говорити» → текст у полі → «Надіслати» → відповідь.
- `uv run pytest -m live tests/live/test_speech_live.py -s` — справжній `gemini-3.5-transcribe` на `eu` записує
  українську фразу дослівно за ~1.2–1.4 с (webm і AAC).
- `uv run pytest -m live tests/live/test_facilitation_language_live.py -s` — фасилітатор: польська → польська;
  людина з українською пише російською → українська (5 з 5); людина з англійською пише українською → англійська.

## Що перевірити голосом на розгортанні
Пункти 10–14 чекліста в `docs/deploy.md` (розділ «F13 — мова і голос (задача 106)»):
1. Сторінка «Мова»: російської немає; зміна мови видна на головній.
2. «🎤 Говорити» → дві-три фрази → текст у полі → «Надіслати»; фасилітатор відповідає вашою мовою.
3. Одна довга репліка на кілька хвилин — текст має з'явитися (так перевіряється, що запис на кілька мегабайтів
   проходить крізь IAP).
4. Те саме з iPhone чи Mac у Safari (інший формат — mp4/AAC; на сервері не було браузера Safari).
5. У журналах — рядки `speech_call` без тексту й без звуку.
Якість на вашому живому голосі (шум, акцент) не вимірювалась: записи для вимірів були синтетичні.

## Рішення, які я ухвалив сам
- Модель розпізнавання — `gemini-3.5-transcribe` (ADR-0005), замість Chirp 3 з карти архітектури: кращий за кожним
  критерієм задачі на вимірах; Chirp 3 не порівняно, бо його API вимкнений, а вмикати API в проєкті мені не дозволено.
- Список мов — усі 85 мов таблиці моделі без російської (включно з тими, що в Google позначені «Experimental», —
  ваш вибір «вільний»); назви — з CLDR, мовою самої мови.
- Запис цілком одним запитом, 64 кбіт/с, автозупинка на 14.5 хв (межа моделі — 15 хв).
- Текст розпізнавання дописується в поле, а не замінює написане.
- Мовне правило фасилітатора — окремим розділом після його правил (`rules.md` не змінено), і заборона російської
  діє навіть для людини, яка ще не обрала мову.
- Smoke голосу запускає Playwright з тимчасового середовища uv (додавати пакет без вашого дозволу не можна).
- Ці рішення й відступи від плану записані в `.engine/overseer/escalations.md` (AUTONOMOUS, двосторонні двері).
