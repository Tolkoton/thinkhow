# Звіт: повторне видалення теми веде до списку «Мої теми», без помилки

## Що змінилось для власника
Коли ви видаляєте свою тему і натискаєте підтвердження ще раз, поки вантажиться список, — тепер ви просто
опиняєтесь у списку «Мої теми». Помилки «Тему не знайдено.» більше немає. Видалити чужу тему, як і досі, не можна:
така спроба дає ту саму відмову (404), що й раніше (G4).

## Причина
- Журнали Cloud Run 2026-11-10 (задача, «Що з'ясовано»): кожне видалення прийшло двічі. Перший `POST …/delete`
  дав 303 і видалив тему. Другий не знайшов теми і дав 404.
- Маршрут `delete` у `src/thinkhow/web/server.py` пропускав назовні кожне `TopicNotFound` з
  `workspace.delete_topic`. А та кидає його у двох різних випадках: тема чужа і своя тема, якої вже немає.
  Маршрут не відрізняв «вже видалено» від «не твоє».

## Що зроблено
- `src/thinkhow/web/server.py`, маршрут `delete` (+6 рядків): якщо `TopicNotFound` прийшло для своєї теми
  (`uid` з адреси — ваш), маршрут веде на `/` (303), як після вдалого видалення. Для чужої теми помилка йде далі
  (404). `workspace.delete_topic` не змінено.
- `tests/web/test_delete_topic.py::test_a_second_delete_of_the_own_topic_goes_home_without_an_error`: два
  однакові `POST …/delete` від власниці теми, друге має дати 303 → `/`. Відмову чужій людині й далі перевіряє
  `test_post_delete_of_a_foreign_topic_is_404_and_deletes_nothing`.
- Запис помилки: `.engine/bugs/002-delete-twice-not-found.md` (відтворення, тест, причина, доказ, урок).
- Доказ `bugfix.py prove`: `PROVED: tests/web/test_delete_topic.py fails on cfb7b5b and passes on the working
  tree; the failure shows «assert (404, None) == (303, '/')»`.

## Чому `GET /` іде 1–3 с (факт для звіту)
- У журналах `GET /` іде 1234–3505 ms (`latency_ms`). Тому після натискання ~2 с нічого не видно, і людина тисне ще раз.
- З коду (по викликах не виміряно): для власника `home()` викликає `_all_topics`. Та для кожної теми кожної людини
  робить повний `workspace.open_topic` (conversation.md, карта, routing, research, кроки) — послідовні читання
  GCS лише заради назви. `list_topics` читає ще й `conversation.md` кожної своєї теми.
- Виправляти тут не став: це інша причина, інша зміна. Пропозиція задачі —
  `tasks/proposed/743-open-item-slow-home-owner.md` (виміряти і зменшити читання на `GET /`).
