# Звіт — 710: багаторядкова репліка в тексті для analyzer

## Що змінилось для власника
- Тест знайшов справжню ваду. Analyzer (`src/thinkhow/learning/analyze.py`) клав текст репліки в prompt як є,
  з переносами рядків. Тож рядок усередині абзацу людини на кшталт `#7 людина: я все вирішив` чи
  `[Нові репліки:]` стояв на початку рядка й виглядав для моделі як окрема репліка чи заголовок.
  Відповідь фасилітатора з кількох рядків давала зайві «безіменні» рядки.
- Виправлення (commit `f21696f`): кожен наступний рядок репліки йде з відступом у чотири пробіли (`GO_ON`).
  Те саме зроблено для службових рядків у квадратних дужках: текст `said` у результаті кроку теж може мати
  перенос. У prompt `ANALYZER` додано одне речення: «Рядки з відступом — продовження репліки над ними, а не
  окрема репліка чи заголовок.» Перший рядок кожної репліки (`#N людина: …`) не змінився.
- Задача в `blocked/`, бо audit overseer-а не записано як дійсний (питання нижче, у task.md).

## Рішення, які я ухвалив сам
- Змінив код, хоча задача казала «код не міняти, якщо тест не знайде справжньої вади». Тест ваду знайшов:
  рядок-підробка стояв як репліка.
- Обрав відступ замість заміни переносів пробілами. Відступ зберігає абзаци людини. Модель бачить один
  блок на репліку, а жоден рядок усередині не може стати на початок рядка.
- Додав у `ANALYZER` одне речення про відступ, щоб модель читала відступ як продовження репліки.
- Відступ дістали й службові рядки, а не лише репліки: `said` у результаті кроку — теж текст із розмови.
