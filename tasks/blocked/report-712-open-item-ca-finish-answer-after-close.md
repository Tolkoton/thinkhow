# Звіт — 712: відповідь фасилітатора дописується, коли вікно закрили

## Що змінилось для власника
- Людина закриває вікно чи втрачає зв'язок посеред відповіді, а сервер усе одно доводить виклик фасилітатора до кінця
  і записує відповідь у `conversation.md`, разом із мапою, routing, research.json і кроком. Повернувшись, людина
  бачить відповідь, а не «Спробуйте ще раз».
  Як це зроблено (`src/thinkhow/web/server.py`, `_Finishing`): потік відповіді читає окремий worker thread, а не
  з'єднання. Запит закінчується лише тоді, коли відповідь записано.
- Новий захист від втрати даних, який ця зміна зробила потрібним. Пізня відповідь (глибоке дослідження йде ~130 с)
  могла б переписати репліки, зроблені тим часом. Тепер `_answer` (`src/thinkhow/workspace/topics.py`) перед записом
  перечитує розмову. Пише лише тоді, коли остання репліка — досі та сама репліка людини без відповіді. Інакше не
  пише нічого, а в журнал іде рядок `reply_superseded` з `uid`, `topic_id`, `turn`.
- Задача в `blocked/`. Код готовий, але audit overseer-а заблокувала вада двигуна; питання — у task.md.

## Відкладене
- Сторінка не знає, що сервер ще дописує. Людина, що повернулась посеред дописування, бачить «Спробуйте ще раз»;
  повтор запускає другий виклик. Дані цілі (I4), зайвий лише виклик моделі. У режимі розмови автоматичний повтор
  тоді отримує 409 і показує помилку, хоча відповідь у темі є, — до перезавантаження. Тригер: рядки
  `reply_superseded` у журналі Cloud Run.
- P3: Cloud Run не забирає CPU, поки запит відкритий, навіть коли клієнт пішов. Локально перевірено, на Cloud Run —
  ні. Перевірка на наступному розгортанні: закрити вкладку посеред відповіді, за хвилину відкрити тему. Якщо
  відповіді немає — варіант `--no-cpu-throttling` (інша оплата; ваше рішення).
- Вада двигуна (печатка після перейменування) — у engine-27, `.engine/to-engine/objection-rename-leaves-stale-seal.md`.

## Рішення, які я ухвалив сам
- Дописування — у веб-шарі (worker thread + черга), а не в `workspace`. Spike
  (`.engine/artifacts/spikes/finish-answer-disconnect-2026-10-28.txt`) показав, що Starlette після розриву просто
  кидає генератор, тож дочитати його в ньому самому неможливо.
- Охоронений запис замість «відповідь у дорозі» на сторінці: дані захищено, а те, що бачить людина, не змінено.
  Зміна сторінки — ваше рішення.
- Між перечитуванням і записом лишається вікно в мілісекунди. Прийнято свідомо: умовний запис сховища — новий
  контракт `Storage` заради нього.
- Базовий набір червоних тестів записав окремим прогоном у чистому git worktree на `0eba1ce`. Перший прогін я
  зупинив, бо поки він ішов, я змінював код.
