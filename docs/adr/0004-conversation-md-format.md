# ADR-0004: Формат `conversation.md` — markdown з маркерами-коментарями

## Status

ACCEPTED — рішення агента (двосторонні двері), 2026-10-22, задача 105, slice skel-workspace (Q1).
Власник бачить у звіті задачі.

Date: 2026-10-22

## Context and Problem Statement

M2 S2 (ADR-0001) назвав файл розмови теми `users/<людина>/<тема>/conversation.md`, а точний формат лишив
рівню коду (M3). Файл читає людина (власник у Cloud Storage), а розбирає код: сторінка розмови (S5) і
нічне навчання (S6), яке посилається на репліки якорем `#t<n>` (G6). Текст реплік пишуть люди, тож формат
мусить витримати будь-який текст і не дати людині підробити номер репліки чи сесію.

## Considered Options

- A. Markdown з маркерами-коментарями HTML (`<!-- thinkhow:turn 3 user <час> -->`), рядки тексту, що
  схожі на маркер або починаються з `\`, екрануються ведучим `\`.
- B. JSON Lines (рядок на репліку).
- C. Markdown із заголовками `### t3 · людина`.

## Decision Outcome

Обрано **A**: у показаному markdown маркерів не видно, файл лишається розмовою для людини, а розбір
однозначний для будь-якого тексту (екранування оборотне — інваріант I1 slice-а). B відкинуто: не
«розмова» для людини. C відкинуто: заголовок може написати сама людина.

### Consequences

- Перший рядок файла — `<!-- thinkhow:format 1 -->`; формат може лише розширюватися новими маркерами.
- Перейти на інший формат пізніше — програма перетворення файлів; поки даних мало, це дешево.
- Задача 202 (2026-10-23): маркер `<!-- thinkhow:closed n <час> -->` код більше не пише в нові файли — кнопки
  «Завершити сесію» немає. Старі файли з ним читаються як і раніше: маркер лишається межею своєї сесії й
  зберігається на місці, коли до файла дописують нову репліку.
