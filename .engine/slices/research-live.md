# Slice research-live — planning artifact

Feature: `.engine/architecture/feature/research-in-conversation.md`, S4 (block evaluation). Driven mode, unattended:
frame supplied by the feature artifact, not asked. Depends on S1, S1b, S2, S3 (all DONE). Builds no product code: a
live evaluation run and its record.

## Goal
Розмова власника #16–#30 (тема `t-d824f508a729`) заново через продукт на справжній моделі `eu` з пошуком: його
репліки #17, #19, #21, #23, #25, #27, #29 дослівно, одна за одною, після його ж історії #1–#16 — і поруч розмова «до»
(як вона є в bucket). Видно, чи на #17, #19, #21 система не питає людину фактів про світ, а шукає (з джерелами) або
пропонує тест (feature AC1, G7, G1); пряме питання про ціну — відповідь з джерелом (AC2, уже live S2 — тут повторно в тій
самій розмові не потрібне). Звіт для власника матиме обидві розмови повністю (AC5). Вимірна ціль: прогін записано —
усі сім реплік мають відповідь, артефакт з обома розмовами, рішеннями роутера, записами `research.json`, часом і
ціною; чи «система не питає фактів», судить власник з артефакту (P4; feature: AC1–AC3 — спостереження, не поріг).

## Seam (contract)
`tests/live/test_research_owner_live.py` (позначка `live`, руками з ADC):
- `owner_turns(conv) -> list[conv_file.Turn]` — репліки людини з номером > 16, у порядку.
- Прогін: `LocalStorage(tmp_path)`, посів Знань з `cards/`, `make_llm(load_settings(environ), …, search=True)` (як у
  `web.app` для Vertex), `facilitate = respond(ctx, knowledge, llm)`, людина `uk-UA`; тема з історією #1–#16 з bucket
  (як є, без `routing.json`), карта — пункти `map.json` з bucket, чий номер `int(turn[1:])` ≤ 16 (числом, не рядком), `phase_id` = `None` (як у
  bucket), `last_turn` = 16 (Q2); перед прогоном тест перевіряє, що серед них є `i3` і `i10` (`router_note` t3, t7) і
  немає пункту з номером > 16, і що проміжки між репліками власника #16–#29 менші за 24 год (одна сесія);
  тоді кожна репліка
  власника > 16 по черзі через `workspace.reply`, час кожної — з `at` репліки власника.
- Вивід `.engine/artifacts/research-live/<час>/conversation.md`: розмова «до» (#16–#30 з bucket) і «після» (#16, потім
  кожна репліка власника і нова відповідь), для кожної відповіді — рішення роутера цієї репліки, запис `research.json`
  (глибина, запити, джерела), пункти `fact`, рядки `llm_call` (час, токени, запити) і ціна за прайсом PR-19.
- Errors: на першому `Failed` — записати і зупинитись (репліка людини вже збережена, сесія відкрита, наступний
  `reply` дав би `PendingAnswer`); тест червоний. Артефакт пишеться **до** перевірок, тож червоний прогін теж лишає
  запис і причину.
- Доказ на кожну відповідь — окремо: `capfd.readouterr()` після кожного `reply` (рядки `llm_call` і ціна — цієї
  відповіді); рішення роутера — новий хвіст `routing.json` (довжина до і після; початок файлу не змінився), а без нового — «без нового рішення
  роутера (картка <id>)»; записи `research.json` — з `turn` = номер цієї відповіді (`Answered.turn_no`).
- Dependencies (injected): `make_llm`, `LocalStorage`, `gcloud` — як у наявних live-тестах.
- Does NOT do: змін коду, оцінки «питає / не питає» кодом, синтетичної людини.

## Decisions (with WHY)
- Q1: репліки власника дослівно, а не синтетична людина — chosen because задача каже «розмова власника #16–#30
  заново», і власник порівнює свої ж слова з двома відповідями. Rejected: синтетична людина (`card_conversations`) —
  інші слова, порівняння «до/після» губиться.
- Q2: без `routing.json` (його в темі немає — продукт кличе роутер, як і зараз), карта — пункти `map.json` з номером
  `turn` ≤ 16 — chosen because найближче до того, що модель бачила на #17 (зокрема `router_note` з t3, t7), без підказок
  майбутнього; наближено: пункт, оновлений пізніше, несе пізніший `turn` і випаде, видалені — втрачені (у виводі
  сказано, з якої карти почали). Rejected: порожня карта (найсильніше: нічого з майбутнього точно немає) — модель
  втратила б усе, що людина сказала до #16, і поводилась би інакше, ніж продукт; повна карта з bucket — підказує пункти
  #19–#29; обрати картку `weighted-matrix`, як live S1, — вже перевірено, а тут продукт як є.
- Q3: «не питає фактів про світ» судить власник, не код — chosen because це якість ведення (P4), а детектор
  «питання про факт» — нова непевна частина (P5). Rejected: класифікатор відповідей моделлю — ще одна модель судить
  модель.

## Hardest seams (test-confidence points)
- **Seam 1: доказ належить своїй відповіді** — після вибору картки роутер нових рішень не дає, а журнал читається з
  виводу: наївний запис показав би `routing[-1]` (рішення #17) для #19–#29 і всі `llm_call` під однією відповіддю.
  Підхід: читання виводу після кожного `reply`, новий хвіст `routing.json`, записи `research.json` за `turn`; у
  живому прогоні перевірити, що кожен розділ має лише свої записи (I1). Anti-pattern: збір доказів раз наприкінці.

## Invariants (rules that hold for every input in the stated domain)
- **I1** — Кожен запис `research.json` і кожне рішення роутера в розділі відповіді N належать відповіді N (`turn` ==
  N для досліджень; рішення — з `turn` репліки людини N−1).
  - Domain: будь-яка з семи відповідей прогону, з карткою чи без, з пошуком чи без.
  - Source: цей контракт, Seam — «для кожної відповіді — рішення роутера цієї репліки, запис `research.json`».
  - Broken by: `routing[-1]` для кожної відповіді; усі записи `research.json` під кожною відповіддю.

- **I2** — Початкова карта прогону — рівно ті пункти `map.json` з bucket, чий номер репліки (`int(turn[1:])`) ≤ 16.
  - Domain: кожен пункт `map.json` (зокрема t3, t5, t7, t9 — номери, що як рядки йдуть після «t16»).
  - Source: цей контракт, Seam — «карта — пункти `map.json` … ≤ 16 (числом, не рядком)».
  - Broken by: порівняння рядків `turn <= "t16"` — губить t3, t5, t7, t9 (зокрема `router_note` `i3`, `i10`).

## Exit criterion
- `uv run ruff check src scripts tests` і `uv run mypy` — кожен окремою командою, чисті; `uv run pytest -q` зелений
  (live-тест виключено позначкою).
- Live (закриває slice): `uv run pytest -q -m live -s tests/live/test_research_owner_live.py` — один прогін; усі сім
  реплік власника отримали відповідь (`Answered`); I1 перевірено в самому тесті; артефакт `.engine/artifacts/research-live/<час>/conversation.md`
  має обидві розмови повністю і для кожної нової відповіді — рішення роутера, записи `research.json`, `llm_call` і
  ціну. Червоний (репліка без відповіді) — slice не закрито, причину — у вивід, без повтору до зеленого. Що система
  робить на #17, #19, #21, — у звіті задачі для власника (P4), без порогу.
