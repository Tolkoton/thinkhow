# Slice spoken-replies — planning artifact

Feature: `.engine/architecture/feature/voice-conversation-mode.md`, S3 (block voice). Driven mode, unattended: frame
supplied by the feature artifact, not asked. Depends on nothing built; S2a already sends `spoken=1` on `/reply`.

## Goal
Коли людина в режимі розмови (а значить, слухає, а не дивиться), модель пише відповідь для вуха її мовою: без
розмітки й символів списку; способи роутера — словами «перший», «другий»; звідки знайдене — назвою сайту чи
організації; коли метод щойно обрано чи почався наступний крок — каже, який метод і який крок; коли метод пройдено чи
не підходить — каже це; пропозицію глибокого дослідження — як досі, з часом очікування. Без режиму розмови кожна
інструкція моделі — та сама до байта. Вимірна ціль: pytest зелений (інструкції з ознакою і без); live на справжній
моделі `eu`: роутер з ознакою пропонує способи без розмітки; відповідь фактом з пошуком називає джерело словами;
перша відповідь обраної картки називає метод (PR-26).

## Premise verified
- Чотири інструкції будуються в чотирьох місцях, і в кожній уже є розділ «# Мова відповіді» з `language_rule`:
  `respond.system_instruction` (`respond.py:77`), `route.router_instruction` (`route.py:84`),
  `answer.answer_instruction` (`answer.py:48`), `deep._system` (`deep.py:155`) — перевірено читанням коду (feature
  critic, round 2, перевірка 2).
- `FacilitationContext` — frozen dataclass, усі поля після `language` мають значення за замовчуванням
  (`types.py:192`), тож нове поле зі значенням за замовчуванням не ламає наявних викликів.
- `/reply` і `/retry` — форми FastAPI; нове необов'язкове поле `spoken` не змінює запитів без нього (`server.py`).
- Рядок «Джерела:» з адресами дописує код (`settle.SOURCES_HEAD`, `deep.py:79`), не модель — його прибирає з голосу
  S2b; модель лише називає джерела словами в самому тексті.
- PR-26 (модель з розділом «людина слухає» говорить так, як просять) — `unverified` до live цього slice.

## Out of scope (deliberately)
- Прибирання рядка «Джерела:» з голосу, сигнали, правила помилок — S2b.
- Зміна правил ведення, роутера чи глибокого циклу поза розділом «# Людина слухає» — N1, P4: ведення те саме.
- Скорочення відповідей заради голосу: P2 (глибина понад стислість) — розділ просить простих речень і головного
  спершу, а не коротших розборів.
- Зберігання ознаки: вона не пишеться ні в `conversation.md`, ні в `routing.json` (feature, Policies).

## Seam (contract)
`src/thinkhow/facilitation/language.py`:
- `LISTENING_SECTION: str` — текст розділу (заголовок `# Людина слухає` і правила нижче), з файлу
  `src/thinkhow/facilitation/listening.md`, прочитаного з `.rstrip("\n")`, як `ROUTED_SECTION` і `DEEP_FIELD`.
- `listening_rule(spoken: bool) -> str` — `"\n" + LISTENING_SECTION + "\n"`, коли `spoken`; `""` — інакше.

`listening.md` (українською, як решта правил):
```
# Людина слухає
Людина зараз не дивиться на екран: вона слухає твою відповідь голосом (наприклад, за кермом). Пиши для вуха,
її мовою за правилом вище:
- Лише звичайні речення: без розмітки, без символів списку, без таблиць, без посилань і адрес.
- Речення прості й не задовгі, головне — спершу; глибина розбору та сама, що й без голосу.
- Кілька варіантів чи способів називай словами: «перший … другий … третій …», кожен — одним-двома реченнями.
- Коли спираєшся на знайдене в інтернеті, скажи словами, звідки це: назвою сайту чи організації (наприклад, «за
  даними ADAC»); адрес не читай.
- Коли метод щойно обрано або ти переходиш до наступного кроку методу, скажи одним реченням, який це метод і який
  крок. Коли метод пройдено або він не підходить, скажи це.
- Пропонуючи глибоке дослідження, як і досі скажи, скільки воно триватиме, і спитай, чи шукати.
Решта правил вище не змінюється.
```

`src/thinkhow/facilitation/types.py`: `FacilitationContext.spoken: bool = False` (останнім полем).

Чотири інструкції — розділ одразу після розділу «# Мова відповіді»: точка вставки — одразу після рядка

- `answer.answer_instruction(language, spoken=False)`; `answer_fact` передає `ctx.spoken`.
- `deep._system(rule, ctx)` — додає `listening_rule(ctx.spoken)` (план, пошук, звіт глибокого циклу).
- Без `spoken` (за замовчуванням) кожна з чотирьох функцій повертає рядок, рівний сьогоднішньому до байта.

## Decisions (with WHY)
- Q1: «для вуха» пише сама модель, розділом інструкції, а не код після моделі. Чому: C4 — сказане людина має почути
  своєю мовою, а написи інтерфейсу українською; модель знає метод, крок і джерела у своєму виклику. Rejected: код
  дописує «Метод: …, крок k з n» і «Джерела: …» до тексту для голосу — українські написи для польської людини, і
  ще один шлях тексту; окремий виклик моделі «переклади для вуха» — +секунди на кожну репліку.
- Q2: розділ — лише з ознакою, без неї інструкції незмінні. Чому: AC2 (звичайний режим як досі) і наявні оцінки
  роутера та карток виміряні на сьогоднішніх інструкціях. Rejected: завжди писати «для вуха» — змінило б ведення в
  тексті без потреби.
- Q3: ознака — поле форми `spoken=1`, а не стан теми чи профілю. Чому: режим — властивість сторінки зараз (людина
  могла вимкнути його посеред теми); не зберігається (feature, Policies). Rejected: прапорець у `profile.json` —
  лишався б після виходу з режиму.
- Q4: P2 — розділ не просить коротших відповідей, лише простих речень і головного спершу. Чому: глибина понад
  стислість; швидкість голосу дає нарізка на речення (S2a), а не скорочення розбору. Рядок feature S3 «вступ глибокого
  і звіт — стисло» тут прочитано як «головне спершу»: AC3 лишає виконавцеві, як стисло («як стисло — вибір
  виконавця»), а P2 ставить глибину понад стислість.
- Q6: розділ стоїть одразу після «# Мова відповіді», тобто в `respond` під роутером — перед `ROUTED_SECTION`,
  `RESEARCH_SECTION` і `DEEP_FIELD`; його рядок «Решта правил вище не змінюється» стосується правил над ним, а
  правила під ним діють як є. Суперечність з `router.md` («пронумеровані способи») розв'язує сам розділ: способи —
  словами «перший … другий». Seam 2 перевіряє, що секції під ним ідуть незмінні. Rejected: розділ у самому кінці
  інструкції — після картки й пам'яті досвіду він губиться серед тексту картки.
- Q5: глибокий цикл теж отримує розділ (план, пошук, звіт). Чому: вступ плану і звіт людина чує; пошукові підвиклики
  тексту людині не дають — розділ їм не шкодить, а `_system` спільна. Rejected: окремо для кожного правила глибокого
  — три розгалуження без користі.

## Hardest seams (test-confidence points — distinct from the contract Seam above)
- **Seam 1: без ознаки — до байта як було.** Оракул — рядки, зняті з коду до slice (commit `cefcb02`) і записані в
  тест як готові очікування, для кількох поєднань (картка, мова зокрема `None`, `routed`, правило глибокого), а не
  зібрані в тесті тими самими шматками, що й код. Відкидає розділ, доданий завжди, і зайвий порожній рядок.
- **Seam 2: з ознакою — розділ рівно раз, після «# Мова відповіді».** Для кожної з чотирьох; у `deep` — для кожного з
  трьох правил (план, пошук, звіт).
- **Seam 3: ознака доходить від форми до контексту.** `POST /reply` з `spoken=1` → `facilitate` отримує
  `FacilitationContext(spoken=True)`; без поля і з `spoken=0` — `False`; `/retry` — так само; у `conversation.md`,
  `map.json`, `routing.json`, `research.json` немає сліду ознаки.
- **Seam 4: live (PR-26).** `tests/live/test_spoken_replies_live.py` на `eu`, через `respond` з `spoken=True`:
  (а) перша репліка ситуації для продумування → роутер `offer`: у `reply` немає `**`, `#`, рядків, що починаються
  з `-`, `*` чи цифри з крапкою (`1.`, `2.` …); (б) пряме питання ціни → `answer` з пошуком: текст відповіді до рядка «Джерела:» містить назву
  хоча б одного джерела словами (домен без зони, напр. `adac`, або назву організації з `title`); (в) «давай перший» →
  `choose`: перша відповідь картки містить назву методу картки (`card.method` або `card.title`) — це перевіряє лише,
  що розділ не шкодить: `JUST_CHOSEN_LINE` уже просить почати з пояснення методу; різницю показує (а), бо
  `router.md` сьогодні просить пронумерованих способів. Кожен прогін пише
  файл у `.engine/artifacts/spikes/`. (б) — збіг без регістру; як і (в), лише «не шкодить» (модель часто називає
  сайти й без розділу). Що означає червоне — у Exit criterion.

## Invariants (rules that hold for every input in the stated domain)
- **I1** — Без ознаки «людина слухає» кожна з чотирьох інструкцій моделі дорівнює тій, що була до slice, до байта.
  - Domain: будь-яка картка ревізії, будь-яка мова профілю або `None`, `routed` так чи ні, кожне правило глибокого
    циклу.
  - Source: feature, S3 («лише коли `spoken`») і контракт S3 → S2a («без поля — як досі»); Q2 цього контракту.
  - Broken by: розділ, доданий без умови; зайвий перенос рядка навколо порожнього `listening_rule`.
- **I2** — З ознакою кожна з чотирьох інструкцій містить розділ «# Людина слухає» рівно один раз, і він стоїть після
  розділу «# Мова відповіді».
  - Domain: ті самі входи, що в I1, з `spoken=True`.
  - Source: feature, S3 («у кожну з чотирьох інструкцій … поруч із «# Мова відповіді»»).
  - Broken by: розділ лише в частині шляхів (напр. забутий у `deep` чи `answer`), подвоєний розділ у `lead` під
    роутером.

## Exit criterion
- `uv run pytest -q` зелений (нові тести slice і всі наявні); `uv run ruff check scripts tests src`, `uv run mypy`,
  `lint-imports` — чисто.
- Live: `uv run pytest -m live tests/live/test_spoken_replies_live.py -s` на `eu` — (а), (б), (в) з Seam 4; вивід у
  `.engine/artifacts/spikes/spoken-replies-live-<UTC>.txt`. Slice DONE лише тоді, коли в записаному прогоні (а), (б),
  (в) зелені. Червоний пункт — PR-26 спростовано для нього: одна правка `listening.md` і ще один записаний прогін;
  червоний і тоді — slice паркується з обома артефактами, не закривається. Повторів того самого тексту до зеленого
  немає. Порогів немає.
- Smoke: `uv run python scripts/smoke_test_spoken_replies.py` — у процесі, як `scripts/smoke_test_skel_learning.py`:
  `TestClient(create_app(deps))`, де `deps` — `build_deps` локального режиму з `facilitate`, зібраною з тим самим
  `respond` і сценарною моделлю, обгорнутою записувачем `system` кожного виклику (обгортка — у скрипті, не в
  `src/`). `POST /reply` з `spoken=1` і без нього → 200 SSE `answered` в обох; у записаних `system` розділ «# Людина
  слухає» є з `spoken=1` і немає без нього. Справжнього uvicorn тут немає: підмінити `facilitate` в окремому процесі
  можна лише зміною `web/local.py`, якої цей slice не робить (critic, round 1).
